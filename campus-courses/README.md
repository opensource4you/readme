# 校園開課

源來適你把社群裡的開源專案帶進大學課堂。一個課程開給台灣多所學校一起上，一學期 16 週，每週 3 小時，前兩週講通用的開源知識，之後每個技術兩週，最後兩週學生報告。

## 目錄

- `common/`：通用週的教材，社團統一維護
- `submissions/<課程>/`：學生繳交，一人一個 md
- 其他目錄：每個技術一個目錄，由負責的小夥伴維護，目錄名與根目錄 README「比較熱鬧的專案」對齊

技術目錄裡怎麼放、教材怎麼寫，尊重各專案的教法，可以互相參考。

## 課程架構

每堂課 3 小時：1.5 小時講解、1 小時動手、剩下當緩衝與 Q&A。第二週講解可縮到 1 小時。

| 週次 | 內容 |
|---|---|
| 1 | 開源入門：開源是什麼、授權、基金會與治理、社群運作。動手：GitHub 設定、第一個 commit |
| 2 | 貢獻流程：Git/GitHub、PR 流程、怎麼讀大型 codebase、溝通禮儀。動手：建立自己的 md，走一次 fork → PR → review → merge |
| 3-14 | 技術 ① 到 ⑥，每個兩週 |
| 15-16 | 期末報告 |

每個技術的兩週：

- 第一週：講專案在解什麼、架構、社群。動手：跑起來、跑一個 test
- 第二週：講核心模組。動手：改一個地方讓行為改變，或重現一個 bug
- 第二週結束前交作業，並介紹社團 Slack 頻道給想繼續的學生

環境在課前裝好，課堂上不處理。

## 期末報告

不給題目。學生針對這學期碰到的技術自己去 repo 探險，找一個有趣的題目或方向來報告。分組，每組 10 分鐘加 5 分鐘問答。

## 繳交

每個學生維護一個檔案 `submissions/<課程>/<GitHub ID>.md`，一學期所有東西都寫在裡面，用 PR 更新。小夥伴或 TA review 後 merge，merge 就是成績紀錄。範例見 [submissions/example/](submissions/example/)。

- 檔案開頭寫學校，每個技術一節，新的在前面
- 簽到：每堂動手完成後，在課堂上 push 一個 commit 加上該週的輸出，commit 時間就是簽到時間
- 作業：第二週結束前補上三項：跑起來的證明、專案在解什麼、看了哪塊程式碼
- 期末：補上題目與投影片連結
- 只能動自己的檔案，貼文字 log 不貼圖，需要圖放外部連結

## 評分方式

| 項目 | 比重 | 說明 |
|---|---|---|
| 出席與課堂參與 | 20% | 簽到 commit |
| 技術作業 | 60% | 6 次，每次 10%：跑起來 5 分、專案在解什麼 2 分、看了哪塊程式碼 3 分 |
| 期末報告 | 20% | 題目是否建立在這學期的技術上、有沒有進到程式碼 |
| 加分 | | 對真實專案開 PR +5，被 merge +10，總分上限 100 |

貢獻不強迫，不計入必要分數。想做的學生進社團 Slack，由小夥伴接手，不佔課程資源。

## 小夥伴分工

- 接技術的：準備兩週教材、上課、review 作業 PR 並打分
- 通用週的：維護 `common/`，帶學生走一次 PR 流程
- 協調的：開課程目錄、核對簽到、排期末報告
- 所有人：期末報告一起打分
