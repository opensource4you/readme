## Highlight：[#73813 Fix dateless dag.test and tasks test destroying unrelated Dag runs](https://github.com/apache/airflow/pull/73813)

**簡介**：在本地跑不帶日期的 `dag.test()` 或 `airflow tasks test`，會把一個沒有日期的 Dag run（例如使用者從 UI 手動觸發的那次）連同它的 task instances 一起刪掉，而且不會有任何錯誤訊息。

**為什麼會這樣**

Airflow 3 開始，手動和 asset 觸發的 run 可以沒有 logical date（存成 `NULL`），但 `dag.test()` 和 `airflow tasks test` 背後的程式還是把「沒給日期」當成「全部都符合」：

1. `get_or_create_dagrun` 會先刪掉佔用同一個 logical date 的舊 run。查詢寫的是 `DagRun.logical_date == logical_date`，`logical_date` 是 `None` 時，SQLAlchemy 會產生 `IS NULL`，於是隨便抓到一個沒有日期的 run 就刪，`task_instances` 也跟著 cascade 刪掉。
2. `DAG.test()` 在那之前還會呼叫 `clear_dags(start_date=logical_date, end_date=logical_date)`。兩個邊界都是 `None` 時，日期條件整個消失，變成這個 Dag **所有** run 的 task instance 都被 clear。

**修法裡的判斷**

- **為什麼「沒有日期就跳過」是安全的**：原本刪舊 run，是為了避免撞到 `(dag_id, logical_date)` 這個 unique key。但 NULL 在 unique key 裡不會互相衝突，所以沒有日期時本來就不需要刪任何東西。
- **`session.commit()` 改成 `session.flush()`**：airflow-core 的規範是被呼叫的函式不能 commit 呼叫端傳進來的 session，這行剛好在這個 diff 裡要移動，就一起改了。
- **行為變化有寫清楚**：連續跑不帶日期的 `dag.test()`，現在每次都會多留一個 run，不會再刪掉上一次的。有帶 `--logical-date` 的情況維持原本的行為。

**怎麼發現的**

這個 bug 是用 Claude Code 檢查程式碼時找到的，詳細經過已經記不清楚。它跟我之前修的 [#72291](https://github.com/apache/airflow/pull/72291) 是同一個指令：#72291 修的是 `airflow tasks test` 沒帶 `--env-vars` 時不會 export `AIRFLOW_TEST_MODE`；這次的問題則在同一個指令往下建立 Dag run 的地方（`task_test` → `_get_ti` → `_get_dag_run` → `get_or_create_dagrun`）。

**驗證**：兩個出問題的地方各補了一個回歸測試。
